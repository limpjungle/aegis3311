# Деградационный режим

> Выдержка из [architecture.md](../00-overview/architecture.md) §5, шаг 6. Источник истины — исходный документ: правки вносить туда, затем синхронизировать этот файл.

## Шаг 6. Деградационный режим

Принцип: потеря связи сужает полномочия, а не продолжает работу «как обычно».

1. **Вход по lease.** Агент переходит в режим по истечении lease, а не по таймауту пинга: это исключает split-brain при частичной потере связи. Control Plane не выдаёт изменяющих команд кластеру без действующего lease.
2. **Разрешённый набор.** Только предодобренные детерминированные действия класса R1 (R2 — если разрешает политика) по кэшированным политикам. По истечении TTL кэша — read-only.
3. **Без свободного reasoning.** Выбор действий силами LLM отключён. Малая локальная модель опциональна и допускается только для суммаризации и классификации (открытый вопрос в §11).
4. **Локальный аудит.** Действия пишутся в собственную подписанную цепочку агента.
5. **Восстановление.** Цепочки сливаются и сверяются с audit Control Plane, локальные действия проверяются на конфликт с текущим состоянием. Прежние уровни возвращаются после реконсиляции.

### Хранилище состояния LLM-роутера (Этап 0a)

- `ErrCorrupt`, `ErrVersion` или `ErrIdentity` при старте (`internal/routerstate`) — роутер не создаётся, LLM недоступен, цели не выше L1. Файл хранилища переносится в сторону для разбора; при старте с пустым хранилищем роутер встанет в `state_lost`. SRE сверяет расход токенов по decision record'ам и делает `Resume`.
- Halt `state_store` (сбой записи во время работы; запросы `not_sent`/`halted`, L1) — проверить диск, перезапустить процесс; если после рестарта halt восстановился по цепочке аудита, снять его через `Resume`.
- Halt `chain_lost` (цепочка аудита пуста, а хранилище состояния содержит учёт: удалена или подменена цепочка) — роутер при старте пишет новый якорь `state_created` и `router_halted(chain_lost)` в новую цепочку и стоит до `Resume`. Бюджеты сохранены (они берутся из store), но предыдущая история аудита потеряна: оператор восстанавливает цепочку из WORM-копии/бэкапа (перед `Resume` проверить `aegis-audit verify`), фиксирует инцидент безопасности и только затем делает `Resume`. Одновременное удаление store и цепочки неотличимо от первого запуска (остаточный риск). Если запись `router_halted(chain_lost)` не удалась, остановка всё равно сохраняется в store, и событие дописывается в цепочку при следующем старте.
- Halt `state_lost` (пустое хранилище при непустой цепочке: в цепочке есть любая запись; при старте с пустой цепочкой роутер пишет якорь `state_created`, поэтому удаление store после первого старта всегда даёт `state_lost`) — расход за сутки и по инцидентам обнулён (бюджеты из цепочки не восстанавливаются), а состояние failover (down/quarantine, активный endpoint) восстановлено из событий цепочки; закрепления инцидентов не восстанавливаются (после `Resume` закреплённый за fallback инцидент может уйти на primary — приемлемо); снимает только человек через `Resume`, решение попадает в аудит. Если не удалась запись якоря `state_created` (или события `router_halted` оборванного перехода) в аудит, роутер не создаётся (`ErrAuditFailed`): починить аудит и перезапустить процесс; при отказе записи intent в store `New` возвращает `ErrStateStore`. `state_lost` затирает прежнюю причину halt (например `auth`): после `Resume` следующий запрос может снова дать `auth`, поэтому перед `Resume` оператор проверяет последние `router_halted` в цепочке. При одновременном отказе store и auth/estimator halt пишется как `state_store`, сигнал 401 (или превышения контекста) в аудит не попадает.

#### Процедура оператора: `aegis-llmrouter` (07.11.2026)

Операторские команды выполняются офлайн: писатель цепочки и store единственный, при работающем `serve` команды получают код 3.

1. `systemctl stop aegis-llmrouter`.
2. `aegis-llmrouter status -config FILE` — проверить `halted`, `halt_reason` и `last_router_halted` (причину, записанную в цепочку). `status` проходит полную сверку старта, как рестарт: может дописать событие и списать незакрытые резервы.
3. Для `chain_lost` — восстановить цепочку из WORM-копии и проверить `aegis-audit verify`. Для `state_lost` — сверить расход по decision record'ам. Для `state_store` и `audit_failed` — проверить диск и ключ подписи.
4. `aegis-llmrouter resume -config FILE -operator ID` — снимает остановку и карантин, пишет `router_resumed`. Если роутер не остановлен и карантина нет, команда завершается с кодом 1 и ничего не пишет.
5. `systemctl start aegis-llmrouter`.

Коды выхода: 0 — успех; 1 — fail-closed (store, цепочка или аудит повреждены или отказали; для `ErrCorrupt`, `ErrVersion`, `ErrIdentity` и `ChainError` см. пункты выше); 2 — аргументы, конфигурация, окружение (в том числе сервис ещё не запускался); 3 — файлы заняты работающим процессом (запущен `serve`: остановите сервис). Ошибка health-loop завершает `serve` с кодом 1, перезапуск — за супервизором; остановку, восстановленную при старте, снимает `resume`.

Конфигурация (JSON, без секретов; секреты — в `OPENROUTER_API_KEY_FILE`, `AEGIS_MASKER_KEY_FILE`, `AEGIS_AUDIT_KEY_FILE`):

```json
{"router_id": "llmrouter-1", "state_path": "/var/lib/aegis/llmrouter.state",
 "audit": {"chain": "/var/lib/aegis/audit.jsonl", "chain_id": "aegis-prod", "public_keys": []},
 "failover": {"fail_threshold": 3, "hysteresis": "10m", "health_interval": "30s"}}
```
