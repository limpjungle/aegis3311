# Алерты фиксации аудита

Правила `audit-anchor.rules.yml` предназначены для prod-intake с обязательной
выгрузкой checkpoint в WORM. Подключите их к внешнему Prometheus, который
доставляет уведомления дежурному через Alertmanager.

В scrape-конфигурации задайте `job_name: aegis-intake-prod` только для этих
экземпляров intake. Настройте адрес `/metrics`, TLS и аутентификацию согласно
параметрам вашего стенда. Для staging используйте отдельный job.

Добавьте файл в конфигурацию Prometheus, указав путь внутри его контейнера
или файловой системы.

```yaml
rule_files:
  - /etc/prometheus/rules/audit-anchor.rules.yml
```

| Алерт | Условие | Реакция |
|---|---|---|
| `AegisAuditAnchorDisabled` | Выгрузка выключена непрерывно 5 минут | Проверить секцию `audit.anchor` и конфигурацию запущенного intake |
| `AegisAuditAnchorLagging` | Возраст самой старой незафиксированной записи больше часа непрерывно 5 минут | Проверить доступность bucket, права ключей, TLS и логи `audit_anchor_lagging` |
| `AegisAuditAnchorErrors` | В окне 15 минут есть ошибки выгрузки, условие сохраняется 5 минут | Проверить логи выгрузки, сеть, права и состояние S3 |

Порог `3600` соответствует `max_lag: 1h` из примера конфигурации intake.
Если меняете `max_lag`, измените порог правила и тесты одновременно.
При выключенном anchor алерты ошибок и отставания подавляются.
Сброс счётчика после перезапуска обрабатывается через `increase`.
Пустая цепочка с нулевым отставанием и отсутствием успешных checkpoint
считается нормальным состоянием.

Если метрики перестали поступать, эти три правила перестанут видеть экземпляр.
Настройте внешний алерт на `up{job="aegis-intake-prod"} == 0` и контроль
наличия ожидаемых targets в вашей системе мониторинга.

Перед подключением выполните из корня репозитория.

```sh
promtool check rules deploy/monitoring/audit-anchor.rules.yml
promtool test rules deploy/monitoring/audit-anchor.test.yml
```

После подключения проверьте загрузку группы в Prometheus и доставку тестового
уведомления дежурному. Результат проверки на целевом стенде внесите в статус
этапа 0a.
