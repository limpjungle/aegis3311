# Принципы безопасности

> Выдержка из [architecture.md](../00-overview/architecture.md) §1; [plan.md](../01-planning/plan.md) §4. Источник истины — исходный документ: правки вносить туда, затем синхронизировать этот файл.

## 1. Принципы проектирования

1. **LLM предлагает — детерминированный каталог исполняет.** Агент не запускает произвольные команды, только действия из каталога (§4.1).
2. **Fail-safe.** При неопределённости система не продвигает изменение и не расширяет полномочия.
3. **Обратимость определяет автономность.** Необратимые действия не выше L1.
4. **Наименьшие привилегии.** У каждого агента своя identity и права только на действия каталога.
5. **Политики применяются в точке исполнения**, в том числе офлайн.
6. **Агент не меняет собственные ограничения:** политики и уровни автономности меняют только люди (принцип четырёх глаз): защищённые пути требуют двух одобрений из разных групп, а подписанный policy bundle, который проверяет агент, выпускает CI только после их повторной проверки ([ci-four-eyes.md](../07-governance/ci-four-eyes.md)). Audit log — append-only: изменять или удалять записи не может никто, ни агент, ни человек.
7. **Любое решение воспроизводимо:** версия модели, контекст и вердикт политики записываются в аудит.
8. **Автономность растёт по данным, а не по календарю.** Повышение уровня опирается на статистику (§4.5).

## 4. Принципы безопасности

- LLM предлагает действия; детерминированный каталог действий их исполняет.
- LLM не получает возможности выполнять произвольные команды.
- Телеметрия, логи, комментарии и тексты PR передаются в LLM как недоверенные данные.
- PEP проверяет каждое действие внутри агента, в том числе при потере связи с Control Plane.
- Изменения защищены lease и fencing tokens: один писатель на цель.
- При потере Control Plane привилегии агента сокращаются; при истечении TTL политик агент переходит в read-only.
- Операции класса R3 (необратимые) не выше L1. Изменение этого правила допускается только человеком через изменение политики (принцип четырёх глаз), но не исключением для отдельного действия.
- Удаление данных и резервных копий запрещено агенту на любом уровне.
- Агент не может менять политики, уровни автономности и audit log, а также approve и merge собственные PR.
- L3 разрешается только для явно разрешённых действий с проверяемыми постусловиями и протестированным rollback.
- Уровень автономности повышается по результатам измерений и утверждения, а не по календарному плану; автопонижение происходит без согласования.
- Данные уходят во внешний LLM только в пределах их класса; для restricted-данных используется локальная модель.
