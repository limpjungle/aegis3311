# Видение и принципы

> Выдержка из [architecture.md](architecture.md): «Обзор», §1. Источник — исходный документ: правки вносить туда, затем синхронизировать этот файл.

## Обзор

AegisOps AI — платформа автономной эксплуатации: от анализа кода до Day-2 в Cloud, Hybrid и Bare Metal. v2 устранила единую точку отказа Control Plane, неконтролируемую автономность ИИ и слабую верификацию. v3 закрывает следующий слой рисков: безопасность самого агента, противоречия в модели автономности, технические неточности и путь внедрения (shadow-режим, критерии выхода по фазам).

## 1. Принципы проектирования

1. **LLM предлагает — детерминированный каталог исполняет.** Агент не запускает произвольные команды, только действия из каталога (§4.1).
2. **Fail-safe.** При неопределённости система не продвигает изменение и не расширяет полномочия.
3. **Обратимость определяет автономность.** Необратимые действия не выше L1.
4. **Наименьшие привилегии.** У каждого агента своя identity и права только на действия каталога.
5. **Политики применяются в точке исполнения**, в том числе офлайн.
6. **Агент не меняет собственные ограничения:** политики и уровни автономности меняют только люди (принцип четырёх глаз). Audit log — append-only: изменять или удалять записи не может никто, ни агент, ни человек.
7. **Любое решение воспроизводимо:** версия модели, контекст и вердикт политики записываются в аудит.
8. **Автономность растёт по данным, а не по календарю.** Повышение уровня опирается на статистику (§4.5).
