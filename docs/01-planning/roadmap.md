## 10. Дорожная карта внедрения

Нумерация фаз совпадает с этапами плана реализации (plan.md). Детальные работы и точные критерии выхода (gates) — в плане; здесь сводка.

| Фаза (этап плана) | Содержание | Критерии выхода |
| --- | --- | --- |
| **Фаза −1 — предусловия** (Этап −1) | Согласования security/legal/DPIA, решение по LLM, read-only доступы, целевой поток, метрики, команда и бюджет | Gate G(−1) |
| **Фаза 0 — основание** (Этап 0a/0b) | Модель угроз и базовый red-team, identity и секреты (SPIFFE, Vault) *(MVP-A: Vault/OpenBao; SPIFFE/SPIRE — MVP-B, решение 09.11.2026, identity-secrets-mvp-a.md)*, каталог действий, kill switch, LLM-роутер, eval-harness, PEP dry-run, shadow-режим (L0), audit log с внешней фиксацией, baseline метрик | Gate G0: shadow ≥ 4 недель, по каждому классу точка ≥ 80% и нижняя граница ДИ не ниже порога, 0 would-be нарушений политик; kill switch проверен учением; baseline зафиксирован |
| **Фаза 1 (P0)** (Этап 1) | PEP в агентах, HA Control Plane на 3 доменах отказа, leases и fencing, fail-closed, матрица автономности, ограничители ИИ, L1/L2 на некритичных сервисах, процесс AI-PR с лимитами, минимальные chaos-проверки Control Plane | Gate G1: failover Control Plane проверен; устаревший fencing token отклоняется; пилот L2 ≥ 60 действий без вызванных инцидентов; доля отмен ниже порога |
| **Фаза 2 (P1)** (Этап 2) | Анализ кода и AI-PR (шаг 1, всегда L1), тесты и mutation testing (ratchet), eval-контур, сборка и GitOps, статистический canary, и только затем L3-rollback | Gate G2: ложные rollback < 5%, recall ≥ 90%; eval-контур блокирует регрессии; canary различает три исхода |
| **Фаза 3 (P2)** (Этапы 3a/3b/3c) | 3a: intake инцидентов, self-healing, sandbox, degraded mode, базовые chaos-сценарии. 3b: адаптеры Cloud/Hybrid, KEDA + Karpenter + буфер, eBPF. 3c: Bare Metal; Digital Twin на K8s-уровне по необходимости | Gates G3a/G3b/G3c: sandbox без побочных эффектов; chaos-сценарии проходят; reconciliation после потери Control Plane; SLO масштабирования (точность прогноза ≥ 80% — вторичная метрика) |
| **Фаза 4** (Этап 4, опционально) | Fine-tuning локальной модели на валидированной обратной связи | Gate G4: модель проходит eval-гейт; стоимость снижена без ухудшения safety-метрик |

Расширение L3 на новые классы действий идёт непрерывно, по правилам §4.5.

## 2. Decision gates

| Gate | Когда | Кто решает | Если не пройден |
|---|---|---|---|
| G(−1) | Конец недели 2 | Спонсор и security | Shadow на prod-данных не стартует; запуск в маскированном или local-only контуре; пересмотр сроков |
| G0 | Конец Этапа 0 | SRE-лид и security | Классы ниже порога остаются на L0/L1; Shadow продлевается для этих классов; при общем провале — остановка и пересмотр RAG, каталога и промптов |
| G1 | Конец пилота L2 | SRE-лид | Возврат на L1, разбор причин, повторный пилот |
| G2 | Перед включением L3-rollback | SRE-лид и владельцы сервисов | Rollback остаётся в режиме рекомендации (L1) или на L2 |
| G3c | Перед Bare Metal | Владелец инфраструктуры | Этап 3c откладывается без блокировки релиза платформы |
| G4 | Перед fine-tuning | Владелец ML | Этап не запускается |

## 3. Зависимости и порядок внедрения

1. Предусловия: согласования, доступы, целевой поток, метрики, бюджет.
2. Threat model, identity, аудит, каталог действий и матрица автономности, kill switch, LLM-роутер, read-only intake, eval-harness, PEP dry-run.
3. Shadow Mode.
4. Control Plane HA, leases и fencing tokens, PEP внутри агента, fail-closed, ограничители ИИ.
5. Уровни L0/L1/L2 и пилот L2 на некритичных сервисах.
6. Анализ кода и AI-PR (L1), eval и тестирование, GitOps, canary и shadow-анализ canary.
7. L3 — только для разрешённых действий, после gate G2, статистической проверки, тестирования постусловий и отката.
8. Self-healing, sandbox, degraded mode, инфраструктурные адаптеры Cloud и Hybrid.
9. Bare Metal, chaos-тесты, reconciliation — по gate G3c.
10. Fine-tuning — после накопления валидированной обратной связи.
